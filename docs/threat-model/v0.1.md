# CyberScan V0 1 Threat Model

## Assets

- Source code.
- Secrets accidentally present in repositories.
- Scanner output.
- Repository metadata.
- Database credentials.
- Security reports.

## Trust boundaries

1. User interface to CyberScan API.
2. CyberScan API to scanner worker.
3. Scanner worker to the analyzed repository.
4. CyberScan services to the persistence layer.

## Initial threats

- Command injection through repository or scanner parameters.
- Path traversal during repository ingestion.
- Secret leakage in logs or dashboard output.
- Scanner process escape or unsafe repository execution.
- Unauthorized access to scan results.
- Silent scanner failure producing incomplete reports.

## Initial controls

- Validate and constrain repository paths.
- Prefer argument arrays and direct process APIs over shell interpretation.
- Run scanners with least privilege and limited filesystem access.
- Redact secrets from logs and reports where possible.
- Record scanner errors as explicit scan events.
- Keep test targets isolated from personal and production systems.
