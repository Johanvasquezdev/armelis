# Armelis V0 1 Architecture

## Purpose

V0.1 establishes the evidence pipeline needed for Armelis to explain security risk without inventing relationships or scan results.

## First vertical slice

```text
Repository
    |
    v
Ingestion
    |
    v
Semgrep / Gitleaks
    |
    v
Scanner adapters
    |
    v
Normalized findings
    |
    v
Persistence
    |
    v
Prioritized findings view
```

## Components

### Repository ingestion

Accept one local Git repository inside an explicit workspace boundary. Record repository identity, branch or commit when available, and scan lifecycle events.

### Scanner adapters

Each adapter invokes one scanner through a controlled process boundary and converts its output into the shared finding contract. Scanner failures must be visible and must not be treated as an empty result.

Initial adapters:

- Semgrep for source-code findings.
- Gitleaks for secret-detection findings.

### Normalization

Normalization standardizes fields while preserving the original scanner payload. It must not claim exploitability, reachability, permissions, or affected assets without evidence.

### Persistence

The initial persistence model stores scans, findings, provenance, lifecycle state, and evidence. PostgreSQL is the target database for the application architecture; a local test database may be used for automated tests.

### Dashboard

The first dashboard answers:

1. What was scanned?
2. Did the scan complete successfully?
3. Which findings need attention first?
4. What evidence supports each finding?
5. What information is still missing?

## Explicit non-goals for V0.1

- Automated exploitation.
- Scanning third-party systems.
- Cloud permission claims without configuration evidence.
- Automatic attack-path claims.
- AI-generated conclusions presented as confirmed evidence.
- Unrestricted shell execution.

## Definition of done

V0.1 is complete when an authorized test repository can be scanned reproducibly, scanner failures are observable, results retain provenance, findings can be reviewed, and the same input produces stable normalized output.
